# 对话画图历史保存与恢复

状态：当前

## 保存位置与迁移

从 `3.2.9-tmsdkdc.3` 开始，对话、原始参考图、当前对话和完成提示保存在同一浏览器、
同一站点的 IndexedDB：数据库 `chatgpt2api-studio`，对象仓库 `state`，键 `snapshot`。
服务器上的图片、图库、任务和调用日志仍使用原有存储。

首次打开新版对话画图时，先读取 IndexedDB；尚无新快照时导入原有 `studio-conversations`
等 localStorage 记录。迁移事务提交后才开放操作。旧键原样保留作为旧格式备份，
后续以 IndexedDB 为准，不继续双写旧存档。不再自动裁掉超过 80 个的对话或每段超过
160 条的消息；存储仍受设备空间和浏览器策略约束。

## 保存失败与刷新

页面显示“正在保存聊天记录…”时，等待写入提交。保存失败会显示常驻错误与“重试保存”，
内存中的最新记录和上次成功快照均保留。点击重试前先保留该页面；普通刷新或离开时，
未完成写入会触发浏览器的离开提示。强制关闭进程、清除站点数据或设备故障无法由该提示保护。
读取失败时不创建空对话覆盖存档，可点击“重新读取”。

聊天记录仍属于浏览器本地数据，不随服务器账号跨设备同步，也不包含在服务器数据备份中。
同一浏览器保持单个对话画图页面，避免旧页面覆盖另一页面的状态。本次没有新增多标签合并。
浏览器开发者工具导出包含完整提示词和参考图，应仅保存在自己的设备，不上传到公开仓库。

## 更新、验收与回滚

沿用 [Fork 更新流程](fork-release.md)，指定已发布的固定镜像标签。更新脚本在服务器备份
配置、运行代码和 `data/` 后重建应用，保留图片、账号和日志。浏览器迁移必须在原来的浏览器、
原站点打开新版后执行，服务器命令无法读取或迁移电脑上的浏览器存储。

更新后确认旧对话和参考图存在，再引用一张已有图片补充生图，等待保存结束，刷新并核对最后一轮。
后台图片和日志也应保持可用。旧版本中已消失、且从未成功写入浏览器存储的消息无法由升级自动找回；
可从服务器日志查看仍然存在的请求和图片。

回滚服务器镜像不会删除 IndexedDB，但旧前端只读迁移前留下的 localStorage 备份，
看不到新版期间新增的历史。保留站点数据并重新部署新版后可重新读取 IndexedDB 中的记录。
